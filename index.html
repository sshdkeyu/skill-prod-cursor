Cursor · production software

The agent writes code the way someone on call would accept it.

Install once. The next edit reads AGENTS.md and the files it names, then applies them. You do not paste a prompt.

curl -fsSL https://sshdkeyu.github.io/skill-prod-cursor/i | bash

The terminal asks first. The default answer is no.

Who it is for

Teams shipping software that already has users. A feature, a bugfix, a diff, an HTTP contract, Go, JavaScript, a list that joins another table, or a live incident.

What you get

  • One floor

    Quality, security, performance, architecture, and AWS sit in rules 00–05. When a skill disagrees, the rule wins.

  • One skill per job

    Solid for application code. Go and JavaScript stay apart. Data access, APIs, review, refactor, and incidents each have a playbook.

  • A case, not a slogan

    Long guidance is bad code, the production cost, and the replacement. The agent copies that shape.

Side by side

Bad

The error is discarded. A truncated payload becomes an empty success.

preprocessed, _ := preprocess(raw)
token, err := parseLine(preprocessed[0])

Good

The error is checked before the value is used. %w keeps the cause.

preprocessed, err := preprocess(raw)
if err != nil {
    return Message{}, fmt.Errorf(
        "preprocess message: %w", err)
}

Stacked

Bad, the cost, then the replacement.

Bad

Load the posts, then read each author inside the loop.

posts = postRepository.findAll()
for post in posts:
    author = post.getAuthor()
    render(post.title, author.name)

Cost

Five posts still feels fine. Fifty posts is 51 round trips. No single statement looks slow, and the tail latency moves.

Good

One join when each post has one author. Name the columns. Bind the ids.

SELECT p.id, p.title, a.name
FROM posts AS p
JOIN authors AS a ON a.id = p.author_id;
